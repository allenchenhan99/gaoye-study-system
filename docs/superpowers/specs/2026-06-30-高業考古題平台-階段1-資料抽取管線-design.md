# 證券商高級業務員 考古題複習平台 — 階段 1：資料抽取管線（Design Spec）

- 日期：2026-06-30
- 狀態：待使用者審閱
- 範圍：本文件只定義「階段 1：資料抽取管線」。階段 2（詳解生成）、階段 3（前端網站）另立文件。

---

## 1. 專案總覽與拆解

目標：把現有的歷屆「證券商高級業務員」考古題（民國 105–115 年）做成一個可練習的網站，支援選年份練習、隨機出題、依科目篩選、錯題本/收藏、模擬考（計時交卷）、答題統計/進度，且每題附詳解。

整個系統拆成三個有先後依賴的子專案，以一份 `questions.json`（題庫）作為串接介面：

```
階段 1：資料抽取管線        階段 2：詳解生成              階段 3：前端練習網站
PDF ─pdftotext─▶ 題庫        題庫 ─Claude─▶ 每題加詳解     React+Vite 讀題庫 JSON
  + 視覺校對/截圖             (全部預先生成) + 驗證答案      年份/科目/隨機/模擬考/錯題本
  + 解析答案表                                              進度存 localStorage
        ▼                          ▼                            ▼
  questions.json             questions.json(enriched)     靜態網站(GitHub Pages/Vercel)
  figures/*.png
```

- 階段 1 產出題庫（題幹、選項、答案、年/次/科目、圖片參照），**不含詳解**。
- 階段 2 只負責「讀題庫 → 補 `explanation` → 寫回」。
- 階段 3 只負責「讀題庫 → 呈現與互動」。

建置順序：先完整完成階段 1（地基、最易出錯）。本文件即階段 1 設計。

**OCR 決策**：採「混合抽取」——所有 PDF 皆有文字圖層，題幹/選項用 `pdftotext`；公式/圖由 Claude 視覺讀取截圖。因此**不使用** baidu/Unlimited-OCR。

## 2. 資料來源現況（已勘查）

- 11 個 zip：`105`–`115`（民國年），多為 Google Drive 下載命名。
- 全部 PDF 皆有乾淨文字圖層（`pdftotext` 可直接抽取，非掃描圖）。
- 兩種命名世代：
  - **舊制 105–109**：中文描述檔名（Big5 編碼，需解碼），多為「每科一檔、50 題」，**答案表通常附在末頁**。
  - **新制 110–115**：數字碼檔名，`11401.pdf` = 民國114年第1次題本（一檔含三科共 ~150 題）、`11401a.pdf` = 對應答案表（單頁）。
- 三個科目：
  - `law` = 證券交易相關法規與實務
  - `investment` = 證券投資與財務分析「投資學」
  - `finance` = 證券投資與財務分析「財務分析」
- 季別/次別：舊制用季（Q1–Q4，4/年）；新制用「第 N 次」（3/年）。
- 估計總題數約 5,000–5,400 題。
- 已知缺口：105 年約 3 份題本末頁未偵測到答案表（需個別處理）。

## 3. 資料模型

`questions.json` 為一個陣列，每筆：

```json
{
  "id": "114-1-investment-001",
  "year": 114,
  "round": 1,
  "roundLabel": "第1次",
  "subject": "investment",
  "subjectLabel": "證券投資與財務分析－投資學",
  "number": 1,
  "stem": "小王兩年來投資某公司股票，第一年期間股價從120元上漲至170元…",
  "options": { "A": "算術平均法，0%", "B": "…", "C": "…", "D": "…" },
  "answer": "C",
  "figures": [],
  "source": "114/11401.pdf",
  "explanation": null
}
```

欄位規則：
- `id` = `年-次-科目-題號`（題號補零 3 位），全域唯一、跨年不重複，是前端與錯題本的鍵。
- `subject` ∈ `law | investment | finance`。
- `round` 為整數（次別或季別數字）；`roundLabel` 為顯示字串（新制「第1次」、舊制「Q1」）。
- `answer` ∈ `A|B|C|D`；無法取得時為 `null` 並進 review 清單。
- `figures`：相對路徑陣列，無圖則空陣列。
- `explanation`：階段 1 一律 `null`，留給階段 2。

**重複題**：跨年重覆題一律全保留（不去重），未來如需可另加標記。

## 4. 管線步驟

每步為獨立 Python 模組，可單獨執行與測試。

| # | 步驟 | 輸入 | 做什麼 | 產出 |
|---|------|------|--------|------|
| 1 | 解壓 + 正名 | `*.zip` | `zipfile` + Big5 解碼修正中文檔名，攤平到 `raw/<年>/` | `raw/` |
| 2 | 檔案分類 | `raw/` | 每個 PDF 判定（年、次/季、科目、是否答案檔）。新制依數字碼；舊制比對中文關鍵字；109 混合命名特例處理 | `manifest.json` |
| 3 | 抽題目 | 題本 PDF | `pdftotext` → 解析器切出每題（題幹＋A/B/C/D）。支援兩種版面：①舊制每科一檔；②新制一檔含三科（用「專業科目：…」標題分段、每科題號重置為 1） | 題目物件（記憶體） |
| 4 | 抽答案 | 答案來源 | 解析答案表：舊制末頁表格／新制 `a.pdf`（含三科分段）。對位 題號 → 答案字母 | 答案表（記憶體） |
| 5 | 合併 | 步驟 3+4 | 題目 join 答案 → 寫出 `questions.json`（`explanation: null`） | `data/questions.json` |
| 6 | 圖/公式處理 | 題本 PDF | `pdfimages -list` 找出夾圖的頁 → 那些題進 review；Claude 視覺讀該頁，截圖存 `figures/`，校對題幹 | `data/figures/*.png` |
| 7 | 驗證 | `questions.json` | 檢查：每題 4 選項＋1 答案、每份 ≈50 題、題號連續。異常題寫入 `review-needed.json` | 驗證報告 |

### 視覺校對流程（控制人工量）

解析器自動產生 `data/review-needed.json`，**只**收錄符合下列任一條件的題：
- 選項解析失敗（找不到完整 A/B/C/D）。
- 題幹/選項疑似跨頁斷裂。
- `pdfimages` 偵測到該頁含夾圖。
- 該份題本末頁無答案表或答案數不符（如 105 那 3 份）。

Claude 僅針對此清單用 Read 工具檢視對應 PDF 頁面，修正 JSON 或截圖；其餘乾淨文字題走全自動流程。

## 5. 目錄結構

```
data/
  questions.json        # 題庫（無詳解）
  figures/              # 截圖
  manifest.json         # 檔案分類結果
  review-needed.json    # 需人工校對清單
raw/                    # 解壓的 PDF（體積大 → .gitignore）
scripts/                # 管線各步驟模組
tests/                  # 單元測試與測試樣本
```

---

## 6. 技術與測試

- 語言：Python。依賴 poppler 的 `pdftotext`/`pdfinfo`/`pdfimages`（已驗證可用）；版面複雜時加 `pdfplumber`。
- TDD：先寫測試再寫解析器。範例斷言：
  - 給定某新制題本，解析出 3 科、各 50 題、題號 1–50 連續。
  - 給定某題，4 個選項皆非空、題幹非空。
  - 抽到的答案 = 人工核對的基準答案（挑數份建立黃金樣本）。
  - 答案表解析：題號→字母對位正確。
- 驗證輸出需可重複執行（idempotent），重跑產生相同 `id` 與結果。

---

## 7. 風險與對策

| 風險 | 對策 |
|------|------|
| 題目/選項跨頁斷裂 | 解析器跨頁接合；偵測不到 4 選項者進 review |
| 選項含「甲乙丙丁」子項 | 解析保留子項文字，不誤切為新選項 |
| 少數無答案表（105 約 3 份） | 進 review；Claude 看 PDF 或標 `answer: null` 待補 |
| 公式/圖遺失 | 步驟 6 截圖補；財務分析較可能含表格 |
| 109 混合命名 | 步驟 2 分類特例處理 |
| 跨年重複題 | 全保留，不去重 |
| Big5 檔名在 macOS 無法直接 unzip | 一律用 Python `zipfile` + `cp437→big5` 解碼 |

## 8. 驗收標準（階段 1 完成定義）

1. `data/questions.json` 產出，且：
   - 每題具備非空 `stem`、4 個非空 `options`、合法 `subject`/`year`/`round`/`id`。
   - 至少 95% 題目具備非 `null` 的 `answer`；其餘列於 `review-needed.json` 並說明原因。
   - 含夾圖的題其 `figures` 指向實際存在的 PNG。
2. `manifest.json` 正確分類全部 PDF（年/次/科目/是否答案檔），無漏檔。
3. `review-needed.json` 列出所有需人工處理項，且 Claude 已逐項處理或標記。
4. 單元測試通過，黃金樣本（人工核對的數份題本）解析結果與基準一致。
5. 管線可從零（僅 zip）一鍵重跑得到相同結果。
